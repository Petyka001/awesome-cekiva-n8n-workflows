# 09 · Content Publishing Factory with Prompt Composition → CEKIVA

> A chat-driven content factory whose system prompt and output schema live in two Google Docs; AI writes the post and an image, you approve by e-mail, and CEKIVA hosts the image and publishes to the network the router chose.

---

## 1. Who is this workflow for?
- **Target Audience:** Agencies and brand teams that keep their voice and rules in shared documents and want an approval step before anything is published.
- **Experience Level:** Advanced n8n user (agents, sub-workflow tools, Google Docs/Drive, send-and-wait approval).

## 2. What problem does it solve?
- **The Manual Pain:** Publishing from an agent pipeline needs a router Switch, a native node or Graph API call per network, expiring Meta tokens, an image host and Merge nodes to rejoin the branches, and prompt changes mean editing the workflow itself.
- **The Automated Solution:** The prompt and schema stay in Google Docs (editable by the team), and everything after the approval is **two requests to CEKIVA**: `POST /v1/upload/image` and **one `POST /v1/posts`** to the chosen network. No ImgBB, Switch, Merge branch or token refresh.

## 3. What do you need? (Prerequisites)
- **Core Platform:** n8n instance (self-hosted or Cloud)
- **Distribution API:** CEKIVA account and API key (`Authorization: Bearer <API_KEY>`, created under *Settings → API keys*). Connect your social accounts once in CEKIVA.
- **External Services & Credentials:** OpenAI API key (router, content and e-mail agents); SerpAPI key (web search tool); Google Docs, Google Drive and Gmail (OAuth2); Telegram bot (optional status messages); Two Google Docs created from the files in [`docs/`](docs).
- **Setup guide:** credentials, the two documents and the options are in [SETUP.md](SETUP.md).
- **Technical Skills:** Basic understanding of importing n8n JSON and setting up credentials.

## 5. What you'll get (End-to-End Delivery)
- **Input Data:** A chat message such as *Create an Instagram post about our spring collection launch*.
- **Automated Processing:** The router agent picks the network, the prompt and schema are composed from your Google Docs, the content agent researches and writes, an image is generated and archived in Drive, and you get an approval e-mail.
- **Final Output:** After you approve: the image uploaded to CEKIVA and one live post on the chosen network, with the result in Telegram.
- **Your Remaining Task:** Write the request and approve (or decline) the e-mail. Declining publishes nothing and uploads nothing.

## 6. A Real-World Example
- **Step 1: Input:**  
  Chat: `Create an Instagram post about our spring collection launch, link to example.com`
- **Step 2: Processing:**  
  The router calls the Instagram tool; the content agent returns `caption`, `call_to_action`, `hashtags` and an `image_suggestion`; the image is archived in Drive and the approval e-mail arrives. After you approve, the image is downloaded from Drive, uploaded to CEKIVA and one `POST /v1/posts` (`platforms: ["instagram"]`) is sent.
- **Step 3: Delivered Result:**  
  The image goes live on Instagram with the caption, call to action and hashtags, and Telegram says `✅ instagram: "…" is scheduled in CEKIVA.` *(Illustrative wording.)*
